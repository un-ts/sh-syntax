# AGENTS.md

## What this repo is

`sh-syntax` is a TypeScript wrapper around `mvdan.cc/sh/v3`, compiled to WebAssembly with standard Go. The parser returns a full, JS-shaped syntax tree; printing formats source text.

## Toolchain

- Node.js >=18 (CI tests 22–26), Yarn 4 (`yarn@4.18.1`)
- Go version is the `go` directive in `go.mod`; Renovate bumps it
- CI uses `actions/setup-go`, pinned by commit SHA

Run `yarn install` once on a fresh clone. The `prepare` script installs `simple-git-hooks` (`nano-staged` + `commitlint`).

## Commands

```sh
yarn install     # dependencies + git hooks
yarn build       # TypeScript/tsdown output in lib/
yarn lint        # ESLint + tsc
yarn test        # vitest, coverage enabled
yarn typecov     # type-coverage check
yarn gen:encoder # regenerate Go encoder, TS AST types, and operator constants
yarn wasm        # gen:encoder + standard Go WASM build + wasm-opt; needs Node >=24.14
```

`yarn format` formats the root repository. `package.json` is owned by `prettier-plugin-pkg`; other JSON/formats go through oxfmt. `shell/` is ignored by the root Prettier config because the submodule has its own formatting setup.

## Layout

- `src/index.ts` — async public entry (`init`, `parse`, `print`, config loading)
- `src/sync/` — synchronous entries: `index.ts` (Node) and `browser.ts` (top-level await)
- `src/browser.ts` — browser entry; fetches the default WASM asset
- `src/workerd.ts` — workerd entry, selected by the `workerd` export condition; imports the bundled WASM as a compiled module
- `src/common.ts` — shared `ParseError` and public ast/operators/source/types re-exports
- `src/internal.ts` — internal WASM invocation helpers
- `src/api.ts` — shared async `parse`/`print` factory used by the entries
- `src/sync/api.ts` — shared sync `parse`/`print` factory used by the sync entries
- `src/processor.ts` — async WASM lifecycle (`init()`) and processor
- `src/ast.ts` — `walk()` (callback or `{ enter, exit }` visitors with `(node, parent, prop, index)`) and `isIncomplete()`
- `src/source.ts` — `createSourceIndex()` from UTF-8 byte offsets to UTF-16 code units
- `src/types.ts` — public AST and option types
- `processor/` — Go parser/printer/envelope and generated encoder
- `scripts/gen-encoder/` — Go generator for the static encoder
- `main.wasm` — committed standard Go WASM build
- `shell/` — `@eslint/shell` fork submodule used for integration testing

## AST contract

- Every node has `type`, `start`, and `end`.
- `start`/`end` and position fields are UTF-8 byte offsets.
- Positions are `{ offset, line, column }`; `line` is 1-based, `column` is 0-based.
- Fields are lowerCamelCase: `stmts`, `cmd`, `args`, `parts`, `redirs`, `lastComments`, etc.
- Nullable fields remain present with `null`; empty slices are `[]`.
- Do not reintroduce Go-style `Pos`/`End` or `NodeType`/`Walk` APIs. Use `node.type` and `walk()`.

## Printing semantics

- `print(text)` formats source text.
- `print(ast, { originalText })` is accepted for compatibility, but the AST is deliberately ignored and `originalText` is formatted.
- `print(ast)` without `originalText` throws a clear `TypeError`.
- `processor(ast, { originalText })` has the same compatibility path in both entries. The sync entry's `getProcessor` accepts bytes, a synchronous loader, or a compiled module. `@eslint/shell` uses `parse` from `sh-syntax/sync`; `prettier-plugin-sh` uses the async `processor`.
- There is no AST decoder in this branch. Do not add a reflective decoder; `print(ast)` with edits is a planned follow-up with a non-reflective wire format.

## Generated files

- `processor/encode_generated.go`, `src/ast-types.ts`, and `src/operators.ts` are generated by `yarn gen:encoder`. Do not hand-edit them.
- `main.wasm` is built by `yarn wasm` with standard Go (`GOOS=js GOARCH=wasm`). All generated files are committed.
- The generator reads `syntax/nodes.go` from `mvdan.cc/sh/v3`; it runs `go mod download mvdan.cc/sh/v3` first so it works with an empty module cache.
- Builds are byte-for-byte reproducible with the pinned Go version and the lockfile-pinned `wasm-opt` (Binaryen 132). CI rebuilds the generated sources and WASM and runs `git diff --exit-code`; keep them in sync in every commit that changes their inputs.
- `wasm-opt@2.0.1` declares Node >=24.14. This only affects `yarn wasm`; the published package still supports Node >=18 because `wasm-opt` is a devDependency. The Build Wasm CI job uses Node 26.
- The WASM build uses `-trimpath -ldflags="-s -w"` and the standard Go runtime GC; TinyGo is tracked separately in #153.

## Tests and snapshots

- Small cases and `test/ast.spec.ts` snapshot the full JS AST.
- Large fixtures snapshot a node-type histogram plus formatted output because a full `install.sh` tree is far too large.
- Update snapshots only for intentional output/AST changes, and inspect the diff.
- Coverage is scoped to `src/**/*.ts`; do not add broad excludes. Keep `src/` flat except `src/sync/`, which holds the sync-only entries; update the coverage glob when the layout changes.

## CI

- `ci.yml` runs on pushes to `main`, pull requests, and merge queues. Do not re-enable every-branch pushes; that duplicates PR runs.
- The `Build Wasm` job regenerates all generated sources and the WASM on Ubuntu, then verifies them.
- The integration job checks out the `shell/` submodule, builds the root package, then installs, builds, and tests `@eslint/shell`.
- `autofix.ci` runs `yarn run-s build format`; it must stay green.
- Keep action pins as full commit SHAs and retain `persist-credentials: false` in the WASM checkout.

## Conventions

- This is a replacement API, not a 1:1 mvdan-sh API. Prefer idiomatic JS: lowercase function names, plain objects, lowerCamelCase fields.
- Add a changeset for user-visible API/behavior changes.
- Avoid reflection, magic numeric modes, and generated wrappers that exist only for a hypothetical future mode.
- When changing the WASM ABI, update Go, TypeScript declarations, and the generated artifact together.
